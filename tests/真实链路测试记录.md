# 真实链路测试记录

日期：2026-11-14。通过本地 FastAPI 接口、运行中的数据库和项目配置的模型、知识库服务执行；未使用 unittest 模拟对象。账户和交易仍是项目演示数据。

本次扩展测试共 29 次请求，涉及 17 个演示会话，均返回 HTTP 200。HTTP 200 只表示接口成功响应，不代表业务回答正确。测试记录保存在本机 `storage/runtime/live-evaluation-20261114.jsonl`，包含演示会话和演示数据，不作为可分享的脱敏报告。

## 发现的问题

1. **PIN 解锁回答混入无依据内容。** 英文提问“如何解锁 PIN”时，回复称连续输错三次后需要联系客户支持重设；混合语言提问时，回复把 App 修改 PIN 和 ATM 修改 PIN 混进了解锁步骤。`data/kb/card_services.md` 将修改 PIN 和解锁 PIN 分别说明：解锁需要在 App 完成 OTP 并重新设置 PIN，并未要求前述客服重设或 ATM 解锁步骤。两次调用分别耗时 26.16 秒和 27.74 秒，生成结果存在不稳定性。
2. **无关问题的拒绝理由不准确。** 提问“今天天气怎么样？”时，回复包含“不能提供投资建议”，虽然拒绝了无关问题，但解释与问题不匹配。
3. **外部模型调用存在连接失败。** 测试期间服务日志出现 HyDE 和 DeepSeek 的连接错误；系统仍能返回回答，但使用了回退路径。应进一步定位网络及模型调用稳定性，再评估回退答案质量和耗时。本次不能将所有回答归因于某个特定生成模型。

## 已验证场景

- 英文、混合语言余额及汇款询问均先要求演示 OTP。
- C001 的汇款查询返回多笔候选；无效编号被拒绝；选中第一笔后可追问第二笔，再询问其他汇款时系统要求选择查询范围。
- C002 的英文 Mum 汇款查询通过演示 OTP 后返回对应演示汇款。
- 连续三次输入错误的演示验证码后，系统停止账户查询。
- 请求冻结演示卡时，系统先要求 OTP，然后要求确认；回复取消后显示未冻结。未测试确认冻结的写入结果。
- 中英文投资建议请求被拒绝；一条英文提示注入被拦截；ATM 吞卡问题返回处理步骤和来源。

上一轮真实接口冒烟测试还验证了中文、英文、混合语言 PayNow 手续费查询、中文 PIN 问答、未验证不能查看客户工单以及验证码通过后查询余额。

测试期间会创建演示会话并写入运行日志，因此不应把本记录中的样本规模作为准确率评估。

## 修复后复测

- 英文和中英混合 PIN 解锁问题改为引用检索原文中的解锁段落；实际接口返回了对应语言的正确步骤和来源。预热后混合语言请求约 2.74 秒，冷启动英文请求约 20.35 秒。
- 天气问题改为一般银行业务范围提示；英文股票投资建议仍被明确拒绝。
- DeepSeek 连接失败时，默认 RAG 回退到检索原文，并只标注实际使用的章节。ATM 吞卡实测返回原文和单一来源，耗时约 24.09 秒。

- PIN 改为走普通混合检索和精排，不调用 HyDE；Agent 模式下也使用该原文路径。尚未进行真实 Agent 模式的端到端回归。

### 新发现并修复：同一会话 OTP 可重试绕过

真实复现发现：连续输错 3 次后，系统虽然回复无法查询，但同一会话重新提出余额查询会再次提示输入 OTP；输入正确演示码即可查到账户余额。这违背了失败后要求联系客户服务的提示。

现已在 LangGraph 跨轮状态中保留 `otp_locked`。达到 3 次失败后，本会话的后续账户查询不再提示 OTP，正确码也不能解锁；真实接口回归确认不能读到账户余额。新建演示会话可正常验证，错误一次后输入正确验证码也仍可正常查询。

新增可重复执行的真实服务回归脚本 `tests/live_api_regression.py`。运行命令和限制见 `tests/README.md`。这轮不创建工单、不发送邮件，也不执行冻结操作。
