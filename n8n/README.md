# 工单分流演示

`ticket-triage.json` 是默认停用的 n8n 工作流：手动运行或定时触发 → 查询待处理工单 → 按紧急程度整理。它只读取工单编号、意图、优先级和时间，不读取客户消息，不发送通知，也不修改工单。

## 使用

1. 在 n8n 编辑器中通过菜单导入 `ticket-triage.json`。
2. 打开“读取待处理工单”节点，选择或新建连接演示 MySQL 的凭据。此机器的本机 n8n 已配置“狮城银行演示 MySQL”。其他环境需重新选择凭据；主机、端口和数据库名应以项目实际配置为准，容器内通常需要使用 Docker 可访问的主机地址，而不是 `localhost`。不要把账号密码写进工作流文件。
3. 点击“手动测试”，检查最后一个节点的 `urgent`、`normal` 和 `notification_status`。如果没有开放工单，MySQL 节点可能没有输出。
4. 保持工作流停用。定时触发只是预留入口：目前没有发送渠道、去重或送达确认，不应当把输出当作已通知坐席。

要接通通知，需要先确定目标渠道，并实现通知状态、重试和去重；不要在重复轮询未解决前启用自动发送。
